# RepoGuard AI — SIH26155 + Open Source Security

A local security workspace with two separate modules: the SIH26155 network-device configuration compliance auditor and an open-source repository security scanner. Repository source is not executed. Public and authorized private GitHub imports fetch source and commit metadata; optional OSV version checks send package names and pinned versions to OSV.dev. The deterministic code/secret scanner and AI-style recommendation heuristics run locally and are not an external LLM.

## Run locally

Requirements: Python 3.10+ and Node.js 20+.

```sh
cd backend
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app:app --reload
```

In a second terminal:

```sh
cd frontend
npm install
npm run dev
```

Open http://localhost:8080. FastAPI docs are at http://localhost:8000/docs. Local audit history and approved mappings are stored in `backend/repoguard.db` (SQLite). Stop the local dev server before starting Docker Compose, which uses the same web port.

## Container deployment

Docker Compose runs the frontend and API together, keeps SQLite data in a named volume, and binds the site to localhost only:

```sh
docker compose up --build -d
```

Open http://localhost:8080. Stop with `docker compose down`; audit data remains in the `repoguard-data` volume. To remove the stored audit data too, run `docker compose down --volumes`.

This prototype has no user authentication, so Compose deliberately binds only to `127.0.0.1`; the backend port is only exposed inside the Compose network. Repository source and private repository URLs are stored in SQLite, whose file is restricted to the app owner (`0600`) where supported. Keep the local machine account protected and do not share the SQLite file. For a remote demo, use a trusted VPN or SSH tunnel to that host. Do not expose port 8080 directly to the public internet. A public or multi-user deployment needs user authentication/authorization, TLS termination, protected backups and storage, secret/config redaction, rate limits, and an operational review before opening network access. No public cloud deployment has been performed.

## Open source security workflow

1. In the dashboard, upload a repository ZIP or paste a GitHub repository URL you choose. Public repositories need no token. For private repositories, enter a temporary fine-grained token with read access to repository metadata and contents. The token is sent to the local backend for that request only, cleared from the form afterward, and never written to SQLite or logs. GitHub imports include up to 30 recent commits.
2. Review Repository browsing, Code Analysis, and Secret Scanner results. Secret values are masked in findings.
3. Review Dependencies and optionally click **Check OSV advisories**. Only exact pinned versions and supported ecosystems are queried; this sends package metadata to OSV.dev. Ranges/unsupported packages are reported as skipped. A no-match is not proof of safety.
4. Download a CycloneDX 1.5 JSON SBOM or the repository assessment JSON report.
5. Review AI Recommendations and Pull Request Suggestions. These are deterministic suggestions, not generated by an LLM; no files or remote pull requests are changed.
6. In Human Approval, record approve/reject and reviewer. Approval records the decision only; a person must implement and submit any code change.

The initial code/secret checks are heuristic and can produce false positives and false negatives. Dependency scanning inventories manifests; OSV lookup is opt-in. This is not a full static analyzer, secret history scanner, malware scanner, license review, or penetration test.

## Network compliance demo workflow

1. Start backend and frontend as above.
2. Choose **Network Compliance** in the sidebar and upload the three synthetic files from `samples/` together.
3. Open Audits and inspect device, framework, evidence line, status, and remediation; download a per-device PDF report.
4. Open a device's unrecognized lines; select one, map it to a supported security field, and confirm approval. Re-upload the sample to see how approved mappings are applied.
5. Explain that “Not Evaluated” means missing recognized evidence, never a pass. Framework coverage is intentionally a small demonstration set, not full certification.

## Supported prototype checks

A small set of deterministic checks is implemented in `backend/app.py` for CIS-style SSHv2 and HTTP-management checks, NIST SP 800-53 remote access and audit logging concepts, a generic administrative idle-timeout STIG-style check, and an ISO/IEC 27001 password protection concept. The IDs are prototype references and are not represented as authoritative benchmark mappings or complete framework coverage. Validate control applicability and exact framework mappings with a qualified assessor before production use.

The current parser recognizes a small syntax subset for Cisco IOS, Fortinet FortiOS and Juniper Junos. It preserves line-level evidence for recognized settings. Unrecognized configuration remains visible for review. Inputs are UTF-8 `.txt`, `.cfg`, or `.conf` up to 1 MB each. Do not upload production configurations or secrets to this demonstration.

## API

- `POST /api/audits` multipart `files` (one or many)
- `GET /api/audits`, `GET /api/dashboard`
- `POST /api/mappings` requires `confirmed: true`
- `GET /api/reports/{audit_id}.pdf`
- `GET /api/health`
- `POST /api/repositories/upload` (ZIP) or `POST /api/repositories/github` (GitHub URL; optional `token` for private repositories)
- `GET /api/repositories`, repository file/browse/commit/dependency/risk/recommendation/PR routes
- `POST /api/repositories/{id}/osv` (optional public OSV query for exact pinned packages)
- `GET /api/repositories/{id}/sbom`, `GET /api/repositories/{id}/report`
- `POST /api/repositories/{id}/approvals` (human decision record)

Mappings use administrator-provided regular expressions and typed normalized values. This prototype has no authentication; bind it to localhost and do not expose it to a network.
